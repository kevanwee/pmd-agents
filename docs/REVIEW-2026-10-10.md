# Review: 0.4.1 to 0.4.2

Reviewed upstream main `01ffad5cc54d3dfc75cbfe719e0542f73c32911a` on 10 October 2026. PR [#1](https://github.com/kevanwee/pmd-agents/pull/1) (PC/catalog/importer) and [#2](https://github.com/kevanwee/pmd-agents/pull/2) (automatic attachment/team dressing) were already merged. There were no open PRs. Both PRs and main had successful source checks. Local main matched upstream and its 55 focused tests passed before changes.

The current architecture is useful: observations feed a separate session reducer; the guild renders that state; the PC supplies cosmetic assignments. Native PMD sheets, pinned catalogs, attribution and local-only observation are retained. The new PC adds a good selection experience, but introduced asynchronous and shared-cache failure paths that the original tests did not exercise.

## Findings addressed in 0.4.2

| Priority | Finding and trigger | Correction and evidence |
| --- | --- | --- |
| High | A catalog failure called `open()` again, immediately requesting the catalog again. An offline source could loop. | Errors stay visible until **Try again** or reopening. Browser check verifies no extra request after an error and exactly one explicit retry. |
| High | An import used whichever teammate was selected when it finished. Switching teammates during download dressed the wrong session. | Capture the original session ID; assign only if it still exists. Browser check switches teammates before the import response and verifies both assignments. |
| High | Multiple windows/importers shared fixed `.tmp` names and independently replaced manifests/receipt arrays, risking lost entries and rename failures. | Unique atomic writes; bounded cross-process locks around manifest and receipt read/modify/write; merge updated receipts by file. Separate-process receipts and overlapping game/species imports have regression tests. Invalid receipt data is preserved and reported. |
| High | `autoAttach` paused only for `ambiguous`, allowing `unavailable` or uninitialized leases to attach unbound hooks. | Require a successful `single` lease. A real VS Code test corrupts the isolated registry, observes automatic detachment while direct terminals survive, then verifies recovery. |
| Medium | Attention forced frame zero even though Idle has native frames. | `!`, `?` and uncertain observations idle in place; no walking or training. Browser check verifies changing Idle frames and stable position, then quiet-mode freezing. |
| Medium | Download limits were checked after buffering the whole body; PNG inflation had no output cap. | Count streamed bytes and cancel at the limit; bound inflation to declared row geometry. Chunked-response and oversized-inflation tests pass. Also fix 16-bit grayscale and transparent RGB/grayscale decoding. |
| Low | README advertised `npm run import:game`, but the script was missing; lockfile still named 0.3.0. | Restore the script and align package/lockfile at 0.4.2. |

Asset failures now reach the requesting PC, and background fetch progress targets the webview that started it. New imports cannot publish a manifest beyond the loader's existing 1,200-sprite/16 MB limits. These are guardrails, not a promise that all catalog forms fit in one eager-loaded pack.

Validation: 61 focused tests with the local pack, TypeScript and production build; Playwright PC/animation/layout checks; isolated real VS Code terminal, transcript discovery, hook routing and lease-loss/recovery checks. Browser assets/events are fixtures; this does not validate a new live Claude session or every catalog form. Source CI skips tests that need the ignored artwork pack.

## Remaining work, in order

1. **Observation lifecycle and recovery.** Make a repeatable matrix for real Codex and Claude sessions: approval/input, cancellation, multiple tools, child agents, extension reload, log rotation and two overlapping windows. Versioned transcript fixtures should be sanitized structural records. Completion always requires evidence. Workspace scope and unbound auto-attachment still do not prove which native window owns a chat.
2. **Asset job manager and repair.** One queue per pack, deduplicate repeated downloads, cancellation when the requesting view closes, per-file retries/backoff, and a visible retry/repair action. Verify existing cache hashes and recover files left without receipts after a crash. A process crash can currently leave a `.lock`: the error identifies it; close all importers and remove that specific lock only after confirming no import is running. Do not silently steal an unknown writer's lock. PMD imports should stage and validate replacements before touching an existing species directory.
3. **Full-Dex scale.** Separate catalog metadata from installed animation metadata. Load only the current clearing's sheets; bound decoded-image memory and move decoding off the extension host. Add large-pack, corrupt-cache, disk-full, offline and panel-close tests. A catalog entry being listed is distinct from its full PMD sheet set being validated and usable.
4. **PC interaction quality.** Keep pending assignments visible; add per-box retry, proper modal focus containment and menu-specific keyboard navigation. Test removed teammates and out-of-order responses as dedicated scenarios. Add artwork-free browser fixtures to CI so interaction failures are caught on every PR.
5. **World polish.** Richer waiting/approval poses where sheets exist, modest arrival/return animations and crowd spacing. Avoid adding combat/expedition systems until observation and asset recovery are reliable.
